# Crypto: передача контекста для доработки

Этот документ — точка входа, чтобы продолжить работу над вкладкой Crypto в новом чате. Общие правила проекта описаны в `CLAUDE.md`, контракт API для бэкенда — в `docs/crypto-screen.md`. Здесь собрано то, чего нет ни там, ни в коде: решения владельца, устройство экрана, подводные камни и что осталось сделать.

## 1. Концепция и решения владельца

Crypto — это **настраиваемый рабочий стол из виджетов**, как домашний экран iPhone. Под поисковой строкой идёт строка готовых разделов от банка.

Что владелец уже решил, не пересматривать без его просьбы:

| Тема | Решение |
|---|---|
| Шапка | Слева логотип: лист Flex, над ним мелкое серое «Flex», под ним крупное мятное «Crypto», как в Figma-макете. Справа аватар профиля. Слева от аватара мятная кнопка с карандашом, оформлена так же, как «+» на Cards |
| Поиск | Компактный, как на Cards (`SearchField size="small"`) |
| Строка разделов | Матовые пилюли высотой с поисковую строку (36pt): стиль стекла, но **без** стеклянных эффектов (обычный `View`: тёмно-зелёная дымка `pillFill`, плотная белая кромка 1pt `pillBorder`, выбранная — мятная `pillSelectedFill` с мятной кромкой и текстом). Переключают контент **под собой**, на месте, без перехода на новый экран. Порядок: Мой стол, Курсы, Новости, Trade, Convert, Фиат, Портфель, Earn |
| Сетка | Как в iOS: 2 колонки, квадратные ячейки, размеры small 1×1, medium 2×1, large 2×2. Виджеты укладываются по порядку в первую свободную ячейку |
| Редактирование | Как в iOS. Карандаш или долгое нажатие на виджет включают режим. Виджеты покачиваются, у каждого появляется «−», их можно перетаскивать. Мятный карандаш растягивается вправо в капсулу «Готово» и накрывает аватар ровно по его месту (`EditControls`), слева появляется круглая «+». Под виджетами — большая пунктирная «+» без текста, второй вход в галерею. На пустом столе заглушка «Здесь пока пусто» с кнопкой видна и в режиме |
| Галерея | Шторка, как в iOS. Виды виджетов — матовые строки-аккордеон (иконка и название крупно, шеврон), раскрыт один за раз. В раскрытом описание и превью размеров с точками, высота пейджера следует за свайпом. Перед добавлением можно выбрать параметры (монету, пару, рост или падение) |
| Хранение | Раскладка — личная настройка пользователя на бэкенде, раскладку по умолчанию отдаёт сервер. Пока это mock в памяти |
| Тап по виджету | Открывает связанный раздел (поле `section` в реестре) |

## 2. Рабочий процесс владельца

- Владелец **сам смотрит UI на своём телефоне** через dev-client. Не запускай симулятор и не собирай нативную часть сам: правило `/simulator` из `CLAUDE.md` здесь не используется. Если попросят «запусти сервер», это `npx expo start --dev-client --lan --clear` в фоне.
- После правок: `npm run typecheck` и проверка, что бандл собирается: `curl -s -o /dev/null -w "%{http_code}" "http://localhost:8081/node_modules/expo-router/entry.bundle?platform=ios&dev=true&minify=false"` должен вернуть `200`.
- Коммитить и пушить только по просьбе. В коммитах не упоминать Claude: никакого `Co-Authored-By`, `CLAUDE.md` и `.claude/` не коммитятся. Работа по Crypto на момент написания **не закоммичена**.
- Конфига prettier в репозитории нет. Если форматировать, то только так: `npx prettier --single-quote --print-width 100 --write <файл>`. Иначе prettier поставит двойные кавычки.
- Владелец пишет коротко и по-русски. Если правка не помогла, он просит откатить, поэтому делай изменения так, чтобы их было легко вернуть.

## 4. Подводные камни (проверено на практике)

- **Liquid Glass не рисуется, если `GlassView` монтируется во время анимации масштаба или прозрачности** (`entering={FadeIn}`, `ZoomIn`). Поэтому переключение разделов идёт **без** анимации, а у пустого состояния стола нет `FadeIn`. Добавлять анимацию появления можно только там, где внутри нет стекла.
- **`GlassGroup` (GlassContainer) рисует стекло детей мимо `overflow: hidden` предков.** Если внутри клипующего контейнера разворачивается что-то стеклянное, ставь его вне `GlassGroup`.
- **SwiftUI-меню (`ActionMenu.ios.tsx`, `Host` + `RNHostView`):**
  - `Host` по умолчанию учитывает safe area и сдвигает кнопку вниз, когда она уезжает под статус-бар. Сейчас стоит `ignoreSafeArea="all"`.
  - С `matchContents` контейнер подгоняет рамку на кадр позже, и содержимое дёргается или обрезается. Если в кнопке меняется содержимое, передавай `triggerSize`, а меняющийся текст держи вне меню.
  - Неактивный пункт меню: `disabled: true` у `ActionMenuItem`.
- **Покачивание** (`WidgetTile`): фаза бежит линейно по кругу, угол и подрагивание — синусы от неё; амплитуда плавно нарастает при входе в режим и затухает при «Готово». Крупные виджеты качаются на меньший угол.
- **Анимации с `ZoomOut`** (удаление виджета) и собственный `transform` на одном `Animated.View` конфликтуют: Reanimated предупреждает, что layout-анимация перетрёт transform. В `WidgetTile` они разнесены по двум вложенным View: внешний отвечает за позицию и удаление, внутренний — за покачивание и подъём.
- **Раскрытие в галерее** идёт без entering-анимации (в превью стеклянные плитки). Высота строки и сдвиг строк ниже анимируются одним `LinearTransition`, а `overflow: hidden` у строки обрезает превью по анимируемой высоте, поэтому большой виджет не перекрывает соседей.
- **Перетаскивание:** `Gesture.Exclusive(pan, tap)`. Pan активируется после долгого нажатия (400 мс вне режима редактирования, 120 мс в режиме), короткий тап открывает раздел. Пока виджет тянется, прокрутка экрана выключена через `Screen.scrollLock` — shared value, которую жест ставит прямо из UI-потока. Через `scrollEnabled` из JS блокировка запаздывала на несколько кадров, и страница успевала съехать за пальцем.
- **Раскладка в mock живёт в памяти.** Новую раскладку по умолчанию видно только после перезагрузки приложения.
- **Всё, что связано с данными пользователя, в mock:** `USE_MOCK_API = true`.

## 5. Что заглушки

- Поиск ничего не ищет.
- ~~Кнопки Trade, Convert и Earn ничего не делают~~ — подключены: «Купить», «Продать» (Trade) и «Обменять» (раздел Convert) открывают шторку обмена `app/exchange.tsx` (сделка по рынку через `POST /convert`), «Подключить» — `app/earn-subscribe.tsx`. Виджет быстрого обмена на столе по тапу ведёт в раздел Convert. Лимитных ордеров нет.
- Список наблюдения всегда показывает BTC, ETH, SOL и USDT. Выбора монет в галерее для него нет.
- Пары в Trade: только BTC, ETH и SOL к USDT, графики — 24 часовые точки с сервера (в `live` — настоящие цены CoinGecko) без выбора периода.
- Новости в разделе «Новости» открываются в браузере по тапу (`url` из RSS сервера); у виджета новостей тап ведёт в раздел, как у остальных виджетов.

## 6. Известные баги и идеи (бэклог)

Владелец отметил «микробаги, некритичные, отладим потом». Конкретно известно:
- При перетаскивании виджетов **разных размеров** соседи могут дёргаться. Целевая ячейка определяется по центру пальца, а сетка переукладывается по порядку, поэтому для 2×1 и 2×2 возможны перескоки туда-обратно. Нужна логика вставки, как в iOS, а не простая перестановка.
- Нет анимации появления нового виджета: `ZoomIn` ломает стекло, см. §4.
- В режиме редактирования размер существующего виджета не меняется. В iOS 18 это можно сделать прямо на столе, у нас только удалить и добавить заново.
- Не проверялось: тёмная тема на новых виджетах, web-версия (`GlassFallback`), VoiceOver для перетаскивания.

Что можно делать дальше, если владелец попросит: настоящий поиск по монетам, выбор монет в списке наблюдения, периоды на графиках (1Д / 1Н / 1М), детальный экран монеты, анимация смены разделов без стекла в момент монтирования, тап вне виджетов как выход из режима редактирования.
