# Экран карт (Cards): спецификация для бэкенда и API

> Статус: фронтенд работает на mock-данных (`src/api/config.ts → USE_MOCK_API = true`).
> Общие соглашения (camelCase, деньги в минорных единицах, ошибки) — см. `docs/home-screen.md`, §2.
> Источник правды по типам — `src/api/types.ts`, по маршрутам — `src/api/services.ts`.

## 1. Что видит пользователь

| # | Блок | Эндпоинт |
|---|------|----------|
| 1 | Карусель пластиков (баланс, •••• last4, VISA/Mastercard, бесконтактная оплата, «заморожена») | `GET /cards` |
| 2 | Лента мини-карт — та же выборка, синхронно с каруселью | `GET /cards` |
| 3 | Действия: Перевод, Пополнить, Заморозить/Разморозить, «Ещё». «Ещё» раскрывает два ряда: Реквизиты, Лимиты, PIN-код, В Wallet, Выписка, Кэшбэк, Перевыпуск, Настройки | заморозка — см. §3 |
| 4 | Реквизиты (номер, срок, CVV, держатель) на обороте карты: тап по карте или кнопка «Реквизиты» переворачивает её, данные скрыты до тапа по ним | `GET /cards/{id}/details` |
| 5 | Операции по выбранной карте: 5 последних, «Все ›» раскрывает весь список, воронка фильтрует по периоду (неделя, месяц, 3 месяца, год, всё время) | `GET /transactions?card_id=…` |
| 6 | «+» в шапке: виртуальная карта, пластиковая (пока недоступна, пункт с замком), привязать карту другого банка | пока без действий |

**Лимит: не больше 6 карт на пользователя** (свои и привязанные вместе, `src/features/cards/cardLimits.ts`). На лимите пункты выпуска и привязки неактивны, а меню объясняет почему. Бэкенд должен проверять тот же лимит при выпуске и привязке. При нарушении он отвечает `409 card_limit_reached`.

## 2. Эндпоинты

### `GET /cards` → `BankCard[]`
```json
[{
  "id": "card_1", "productName": "Flex", "brand": "visa", "kind": "debit",
  "last4": "4821", "balance": { "amountMinor": 420000, "currency": "BYN" },
  "style": "mint", "status": "active", "contactless": true
}]
```
- `brand`: `visa | mastercard`; `kind`: `debit | credit`; `style`: `mint | dark | grey | purple` (оформление пластика); `status`: `active | frozen`.

### `GET /cards/{id}/details` → `BankCardDetails` (новый)
Реквизиты запрашиваются **только когда пользователь нажал на скрытые данные** на обороте карты,
отдельно от списка карт, и не кэшируются клиентом дольше минуты. Перед запросом клиент проходит
проверку доступа (`src/features/cards/sensitiveAccess.ts`): сейчас это заглушка, позже — пароль
или Face ID. Когда она появится, бэкенду, вероятно, понадобится подтверждение (короткоживущий
токен) в заголовке этого запроса.
```json
{ "cardId": "card_1", "pan": "4532718209344821", "expiry": "08/29", "cvv": "417", "holderName": "ROMAN PONYAVIN" }
```
- `pan` — 16 цифр без пробелов; `expiry` — `MM/YY`; `holderName` — латиницей, как на пластике.
- `404 card_not_found` — карты нет или она не принадлежит пользователю.
- Рекомендации: отдавать только по свежей сессии (в будущем — после повторной аутентификации), логировать доступ.

### `GET /transactions?card_id=…`
Контракт тот же, что на Home. Экран берёт все операции карты (новые первыми) и сам режет их на 5 /
весь список и фильтрует по периоду на клиенте. Когда операций станет много, понадобятся
пагинация и параметр периода (например, `from=<ISO-дата>`) — фильтр уже готов передавать его.

## 3. Пока не в контракте
- **Заморозка/разморозка**: клиент меняет статус только локально. Нужен, например,
  `POST /cards/{id}/freeze` и `POST /cards/{id}/unfreeze` → обновлённый `BankCard`.
- Лимиты, PIN-код, Wallet, выписка, кэшбэк, перевыпуск, настройки — кнопки есть, обработчиков нет.
- Выпуск пластиковой и виртуальной карты, привязка карты другого банка — пункты меню «+» есть, обработчиков нет.
