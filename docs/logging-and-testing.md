# Логирование и тестирование клиента (отчёт 6/1)

## 1. Логирование

Логи пишутся в модуле `src/logging` и пачками уходят на сервер: `POST /api/v1/client-logs`. Формат и способы анализа на стороне сервера описаны в flex-be/docs/logging.md.

| Файл | Назначение |
|---|---|
| `src/logging/logger.ts` | логгер: уровни, подсистемы (`child`), буфер, пачки, повтор, вытеснение старых записей |
| `src/logging/transport.ts` | отправка пачки `fetch` с `keepalive`, разбор `429 Retry-After` |
| `src/logging/redact.ts` | очистка `context` от паролей, токенов, PIN, данных карт, циклов и длинных строк |
| `src/logging/globalHandlers.ts` | необработанные ошибки (ErrorUtils на iOS/Android, `window.onerror` и `unhandledrejection` на web), отправка буфера при уходе в фон |
| `src/logging/ErrorBoundary.tsx` | ошибка рендера показывает заглушку с «Повторить» вместо белого экрана и попадает в лог |
| `src/logging/useScreenLogging.ts` | просмотр экрана, маршрут подставляется во все следующие записи |
| `src/logging/index.ts` | общий экземпляр `logger`: id сессии, платформа, версия |

Где логи вызываются:

| Место | Что пишется |
|---|---|
| `src/api/client.ts` | каждый HTTP-запрос: debug — успех с длительностью, warn — 4xx с кодом, error — 5xx и сбой сети. Тело и заголовки не пишутся, query отрезается |
| `src/api/authInterceptor.ts` | refresh, принудительный выход, блокировка Crypto сервером |
| `src/auth/sessionActions.ts` | вход (тип логина, без самого логина), неудачный вход, выход с причиной, ошибка refresh |
| `src/api/chat/client.ts` | закрытие WebSocket, затянувшееся переподключение |
| `src/api/queryClient.ts` | неудачные запросы и мутации react-query |
| `app/transfer.tsx`, `app/exchange.tsx` | перевод и обмен: успех и отказ (валюта и код, без сумм и телефонов) |
| `app/_layout.tsx` | старт приложения, глобальные обработчики, ErrorBoundary, экраны |

Правила отправки:
- Ошибка уходит сразу: после неё приложение может упасть.
- Остальное уходит каждые 10 с, при заполнении пачки (20 записей) и при уходе в фон или закрытии вкладки.
- Если сервер недоступен, пачка возвращается в очередь. Пауза равна `Retry-After` или 10 с. В памяти держится до 200 записей, старые вытесняются.
- На сервер уходят записи уровня info и выше, в dev ещё и debug. Порог меняет `EXPO_PUBLIC_LOG_LEVEL`. В mock-режиме сервера нет, поэтому логи идут только в консоль.
- Логирование идёт мимо `api`/`withAuth`: оно не запускает refresh и не логирует само себя.

## 2. Тестирование

Используются Jest (`jest-expo`) и React Native Testing Library. Запуск: `npm test`, с покрытием — `npm run test:coverage`. В CI тесты идут после `typecheck`.

| Тесты | Что проверяют |
|---|---|
| `src/logging/__tests__/logger.test.ts` | пачки, уровни, немедленная отправка ошибки, порядок после сбоя, `Retry-After`, вытеснение, таймер |
| `src/logging/__tests__/transport.test.ts` | URL, заголовки, токен, реакция на 429/500/422/сбой сети |
| `src/logging/__tests__/redact.test.ts` | очистка секретов, циклы, обрезка; код ошибки сервера не вычищается |
| `src/logging/__tests__/globalHandlers.test.ts` | необработанное исключение уходит на сервер, уход в фон отправляет буфер |
| `src/logging/__tests__/useScreenLogging.test.tsx` | хук: просмотр экрана и маршрут в записях |
| `src/logging/__tests__/ErrorBoundary.test.tsx` | компонент: заглушка, запись со стеком компонентов, «Повторить» |
| `src/api/__tests__/client.test.ts` | HTTP-клиент: токен, разбор ошибок FastAPI, уровни логов, пароль не попадает в лог |
| `src/ui/__tests__/ErrorState.test.tsx` | компонент: тексты i18n, кнопка и колбэк |
| `src/features/auth/__tests__/PinPad.test.tsx` | компонент: кнопки и подписи для VoiceOver, disabled, биометрия |
| `src/features/auth/__tests__/PinDots.test.tsx` | компонент: закрашенные точки, озвучивание, вибрация при ошибке |
| `src/auth/__tests__/validation.test.ts`, `src/features/operations/__tests__/amount.test.ts`, `src/features/auth/__tests__/authErrors.test.ts`, `src/utils/__tests__/money.test.ts`, `src/utils/__tests__/format.test.ts` | модульные: телефон, email, PIN, сумма в минорных единицах, тексты ошибок, форматирование денег и дат |

Окружение тестов: `jest.setup.js` (русская локаль, моки reanimated и worklets), `src/test/render.tsx` (тема и i18n вокруг компонента).

Особенности тестирования клиента:
- **Нативные модули.** Анимации, haptics, Keychain и камера в Node не работают, поэтому их подменяют моками. Тест проверяет логику и разметку, а не то, как выглядит экран на устройстве.
- **Асинхронность и время.** Таймеры, сеть и состояние React меняются не сразу. Нужны `await` вокруг render и событий, фейковые таймеры и подставные часы (`now`).
- **Окружение пользователя.** Компоненту нужны тема, перевод и провайдеры. Без них он не рендерится.
- **Проверка с точки зрения пользователя.** Элементы ищутся по тексту и роли с подписью (`getByRole('button', { name: 'Цифра 1' })`), а не по внутренним полям. Это заодно проверяет доступность.
- **Сеть и сервер.** `fetch` подменяется. Проверяется, что клиент отправил и как он реагирует на 4xx, 5xx и обрыв связи. Сервер тестируется отдельно (pytest во flex-be).
- **Платформы.** Код с `.ios.tsx` и `.web.tsx` ведёт себя по-разному. Jest-expo по умолчанию собирает iOS-вариант, web проверялся ручным прогоном.
