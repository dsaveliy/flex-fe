# Главный экран (Home): спецификация для бэкенда и API

> Статус: фронтенд экрана готов и работает на mock-данных (`src/api/config.ts → USE_MOCK_API = true`).
> Этот документ описывает, какие данные экран запрашивает, в каком формате их ждёт и как их использует.
> Цель — чтобы бэкенд (FastAPI) отдавал ровно эти контракты, и переключение на реальный API
> делалось одной строкой без правок экрана.

Источник правды по типам — `src/api/types.ts`, по маршрутам — `src/api/services.ts`,
пример данных — `src/api/mock/fixtures.ts`.

---

## 1. Что видит пользователь

Экран сверху вниз:

| # | Блок | Данные | Эндпоинт |
|---|------|--------|----------|
| 1 | **Шапка**: приветствие по времени суток («Добрый вечер,»), имя, значок солнца/месяца, аватар справа (ведёт в профиль) | имя, фамилия (инициалы), фото | `GET /me` |
| 2 | **Общий баланс**: крупная сумма, переключатель валюты «BYN ▾», кнопка-глаз «скрыть баланс», процент изменения за выбранный период | итог, счета, история | `GET /balance` |
| 3 | **График баланса** с периодами 1Д / 1Н / 1М / 1Г / Всё. Пальцем можно вести по графику: сумма и дата показывают значение в точке | история по периодам | `GET /balance` |
| 4 | **Быстрые действия**: Перевод, Пополнить, Купить крипто, «Ещё» → Обменять / Оплатить / Вывести | пока без действий | — (см. §6) |
| 5 | **Промо-баннер** «Деньги работают на вас / До 4,5% годовых» | пока статичный текст | (`GET /promo` есть в контракте, экран пока не использует) |
| 6 | **Последние операции**: 3 последние, ссылка «Все ›» на вкладку Карты | операции | `GET /transactions?limit=3` |

Состояния, которые обрабатывает экран:
- **загрузка**: скелетоны на месте баланса, графика и операций;
- **ошибка**: блок «Что-то пошло не так» с кнопкой «Повторить», отдельно для баланса и для операций;
- **обновление**: pull-to-refresh перезапрашивает `/balance`, `/me`, `/transactions`.

### Стиль (для контекста)
Тёмная тема по умолчанию, iOS 26 Liquid Glass (системный таб-бар, стеклянные кнопки и меню),
мятный акцент `#248C66`, шрифт Inter. Сумма крупная (52 pt), цифры «перекатываются» при изменении,
за суммой — декоративная Σ из макета, которая смещается при наклоне телефона.
Всё это чисто клиентское и на API не влияет.

## 2. Общие соглашения API

### 2.1 Формат полей — camelCase
HTTP-клиент (`src/api/client.ts`) **не преобразует регистр**: JSON парсится как есть и сразу
используется как TypeScript-типы. Поэтому ответы нужны в **camelCase** (`amountMinor`, `occurredAt`).

Для FastAPI/Pydantic v2 это делается так:
```python
from pydantic import BaseModel, ConfigDict
from pydantic.alias_generators import to_camel

class ApiModel(BaseModel):
    model_config = ConfigDict(alias_generator=to_camel, populate_by_name=True)
# и в роутах: response_model_by_alias=True (по умолчанию)
```
Query-параметры остаются в snake_case: `?card_id=...&limit=3`.

### 2.2 Деньги
Деньги всегда передаются **целым числом минорных единиц + код валюты**, никаких float:
```json
{ "amountMinor": 1248050, "currency": "BYN" }   // 12 480.50 BYN
```
- Фиат: 2 знака (`amountMinor` = копейки/центы).
- Крипта: 8 знаков (сатоши для BTC). Число знаков дополнительно передаётся в `amountDigits` (см. `AccountBalance`).
- Базовая валюта приложения — **BYN**.

### 2.3 Даты
ISO 8601 с часовым поясом: `"2026-10-08T18:42:00+03:00"` или UTC с `Z`.

### 2.4 Ошибки
Клиент сейчас смотрит только на HTTP-статус: любой не-2xx → экран показывает состояние ошибки,
React Query делает **1 повтор**. Предлагаемый формат тела ошибки (клиент готов его читать —
тип `ApiErrorShape`):
```json
{ "code": "balance_unavailable", "message": "Человекочитаемое описание" }
```

### 2.5 Кеширование на клиенте
`staleTime` 30 с, повтор 1 раз, без перезапроса при возвращении в приложение. Ответы
кешируются по ключам из `src/api/queryKeys.ts`. Заголовки HTTP-кеша не нужны.

### 2.6 Авторизация
Пока не реализована: клиент не шлёт токен. Все эндпоинты ниже — от лица текущего пользователя
(`/me`, а не `/users/{id}`). Когда появится auth (PIN/биометрия из README), нужно договориться
о схеме (предлагается `Authorization: Bearer <jwt>`).

## 3. Эндпоинты экрана

### 3.1 `GET /me` — текущий пользователь
```ts
type User = {
  id: string;
  firstName: string;
  lastName: string;
  avatarUrl: string | null; // null → клиент рисует инициалы
};
```
```json
{ "id": "usr_1", "firstName": "Роман", "lastName": "Понявин", "avatarUrl": null }
```
Используется: имя в приветствии, инициалы в аватаре, полное имя в профиле.
Приветствие («Доброе утро» и т.д.) клиент выбирает сам по **локальному времени устройства**.

---

### 3.2 `GET /balance` — общий баланс, счета и история (главный эндпоинт экрана)
```ts
type BalancePeriod = '1D' | '1W' | '1M' | '1Y' | 'ALL';

type BalanceSummary = {
  total: Money;                                 // итог в базовой валюте (BYN)
  monthChangePercent: number;                   // изменение за месяц, %: 2.4 = +2.4%
  history: Record<BalancePeriod, number[]>;     // ряды значений итога по периодам
  accounts: AccountBalance[];                   // все счета пользователя
};

type AccountBalance = {
  id: string;
  currency: string;          // BYN | USD | BTC | ETH ...
  kind: 'fiat' | 'crypto';
  name: string;              // «Белорусский рубль», «Bitcoin»
  amount: Money;             // остаток в валюте счёта
  amountDigits: number;      // знаков в amount.amountMinor: 2 для фиата, 8 для крипты
  valueBase: Money;          // стоимость счёта в BYN по текущему курсу
  changePercent: number;     // изменение стоимости счёта, %
  color: string;             // hex для значков и графиков, напр. "#F59933"
  series: number[];          // мини-график счёта (~24 точки)
};
```

**Пример** (сокращён):
```json
{
  "total": { "amountMinor": 1248050, "currency": "BYN" },
  "monthChangePercent": 2.4,
  "history": {
    "1D":  [12401.12, 12398.40, "... 48 точек ...", 12480.50],
    "1W":  ["... 42 точки ...", 12480.50],
    "1M":  ["... 60 точек ...", 12480.50],
    "1Y":  ["... 52 точки ...", 12480.50],
    "ALL": ["... 60 точек ...", 12480.50]
  },
  "accounts": [
    {
      "id": "acc_byn", "currency": "BYN", "kind": "fiat", "name": "Белорусский рубль",
      "amount": { "amountMinor": 673950, "currency": "BYN" }, "amountDigits": 2,
      "valueBase": { "amountMinor": 673950, "currency": "BYN" },
      "changePercent": 0.4, "color": "#248C66", "series": [100, 100.2, "..."]
    },
    {
      "id": "acc_btc", "currency": "BTC", "kind": "crypto", "name": "Bitcoin",
      "amount": { "amountMinor": 4120000, "currency": "BTC" }, "amountDigits": 8,
      "valueBase": { "amountMinor": 352010, "currency": "BYN" },
      "changePercent": 4.8, "color": "#F59933", "series": [100, 101.3, "..."]
    }
  ]
}
```

**Инварианты, на которые опирается клиент:**
1. `history[*]` — числа в **основных единицах BYN** (`12480.50`, не минорные), упорядочены от старых к новым.
2. **Последняя точка каждого ряда = `total`** (в основных единицах). Иначе при отпускании пальца сумма «прыгает».
3. Точки ряда идут **через равные интервалы** внутри периода — дату точки под пальцем клиент
   вычисляет сам: `now − длительность_периода × (1 − i / (n − 1))`.
   Длительности: 1D = 24 ч, 1W = 7 дн, 1M = 30 дн, 1Y = 365 дн, ALL = 3 года.
   Для 1D подпись — время (`18:40`), для ALL — дата с годом (`8 мар. 2024`), иначе день и месяц.
4. Количество точек — на усмотрение бэкенда, минимум 2. Сейчас: 1D — 48 (каждые 30 мин),
   1W — 42 (каждые 4 ч), 1M — 60, 1Y — 52 (по неделям), ALL — 60. Больше ~100 не нужно —
   на экране шириной ~400 pt это не видно, а скраббинг станет слишком «мелким».
5. **Процент изменения за период клиент считает сам** из ряда: `(последняя − первая) / первая × 100`.
   `monthChangePercent` сейчас используется как запасной и для подписи «за месяц».
6. `Σ accounts[].valueBase = total` (с точностью до копейки).

> ⚠️ Если бэкенду удобнее отдавать точки с метками времени (`[{ "t": "...", "v": 12480.5 }]`)
> или неравномерные интервалы — это нормально, но нужно предупредить: клиент поменяет
> вычисление дат (правка на ~10 строк). Обсудить до реализации.

### 3.3 `GET /exchange-rates` — курсы для пересчёта баланса
```ts
type DisplayCurrency = 'BYN' | 'USD' | 'EUR' | 'BTC';

type ExchangeRates = {
  base: 'BYN';
  rates: Record<DisplayCurrency, number>; // сколько BYN стоит 1 единица валюты
  updatedAt: string;                      // ISO 8601
};
```
```json
{ "base": "BYN", "rates": { "BYN": 1, "USD": 3.27, "EUR": 3.55, "BTC": 85440 }, "updatedAt": "2026-10-08T18:40:00Z" }
```
- Семантика: **BYN за 1 единицу**: `USD: 3.27` → 1 USD = 3.27 BYN. Значение для `BYN` всегда `1`.
- Пользователь может показать общий баланс в BYN / USD / EUR / BTC (меню «BYN ▾» на Home
  и пункт «Валюта баланса» в профиле). Пересчёт делается **на клиенте**: `total / rates[валюта]`,
  то же для каждой точки графика. Процент изменения от валюты не зависит.
- Точность показа: фиат — 2 знака, BTC — 4 знака (`0.1461 BTC`).
- Пока курсы не загрузились, баланс показывается в BYN.
- README упоминает таблицу `exchange_rates` — этот эндпоинт должен отдавать её актуальный срез.
- ⚠️ В моках курс BTC (85 440) занижен, чтобы совпасть с фикстурой счёта. Реальные данные
  должны быть согласованы: `accounts[BTC].valueBase ≈ amount × rates.BTC`.

### 3.4 `GET /transactions?limit=3` — последние операции
Тот же эндпоинт использует вкладка «Карты» (с `card_id` и без `limit`).
```ts
type Transaction = {
  id: string;
  cardId: string;
  merchant: string;            // «MAK.by», «Yandex Go», «Spotify»
  category: 'shopping' | 'salary' | 'cafe' | 'transport' | 'transfer' | 'subscription' | 'other';
  direction: 'incoming' | 'outgoing';
  amount: Money;               // всегда положительная, знак задаёт direction
  occurredAt: string;          // ISO 8601
};
```
Query-параметры: `limit` (int, опционально), `card_id` (string, опционально).

Требования:
- сортировка **от новых к старым** — клиент берёт первые `limit` без пересортировки;
- `amount.amountMinor` **> 0**; клиент сам рисует `+` (зелёным) для `incoming` и `−` для `outgoing`;
- дата показывается как «8 окт.» по локали устройства.

> Пагинация для полного списка понадобится на экране операций (cursor-based, `?cursor=&limit=`) —
> для Home не нужна.

## 4. Что делается только на клиенте (бэкенду не нужно)

| Функция | Где хранится | Замечание на будущее |
|---------|--------------|----------------------|
| Скрыть баланс (глаз, тап по сумме, свитч в профиле) | память приложения | Можно сохранять в `GET/PATCH /me/settings` |
| Валюта отображения баланса | память приложения | То же — поле `displayCurrency` в настройках |
| Тема (светлая/тёмная), язык (RU/EN) | память приложения | То же |
| Приветствие по времени суток | время устройства | — |
| Процент за период, даты точек графика, пересчёт валют | вычисляется из `/balance` и `/exchange-rates` | — |

Если бэкенд добавит настройки пользователя, предлагаемый контракт:
```json
GET  /me/settings  → { "hideBalance": false, "displayCurrency": "BYN", "theme": "dark", "language": "ru" }
PATCH /me/settings ← { "displayCurrency": "USD" }
```

## 6. Что понадобится дальше (кнопки действий уже на экране)

Кнопки отрисованы, но пока ничего не делают. По README и макету им понадобятся:

| Кнопка | Сценарий | Вероятные эндпоинты |
|--------|----------|---------------------|
| Перевод | P2P по номеру телефона | `POST /transfers` |
| Пополнить | пополнение счёта/карты | `POST /topups` |
| Купить крипто | покупка BTC/ETH за фиат | `GET /exchange-rates`, `POST /exchanges` (quote → confirm) |
| Ещё → Обменять | обмен crypto ↔ fiat | `POST /exchanges/quote`, `POST /exchanges` |
| Ещё → Оплатить | крипто-эквайринг (оплата с автоконвертацией) | `POST /payments` |
| Ещё → Вывести | вывод крипты на внешний адрес | `POST /withdrawals` |

Контракты этих операций согласуем отдельно, когда дойдём до экранов.

## 7. Открытые вопросы к бэкенду

1. **camelCase в ответах** — ок через `alias_generator=to_camel`? (§2.1)
2. **История баланса** — равномерные точки без меток времени (как сейчас) или `{t, v}`? (§3.2)
3. **Откуда считается история** — снапшоты баланса по расписанию или пересчёт по операциям
   и курсам? От этого зависит, насколько «живым» будет 1D.
4. **Источник курсов** и частота обновления `exchange_rates` (для 1D важна свежесть BTC).
5. **Формат ошибок** — `{ code, message }` подходит? (§2.4)
6. **Авторизация** — схема токенов и эндпоинт входа (§2.6).
7. Нужен ли **`GET /me/settings`** для синхронизации настроек между устройствами (§4)?
